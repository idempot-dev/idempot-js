# Proposal

## Why

`tests/spec/idempotency.feature` is the artifact the project points at when it claims
IETF compliance, yet it cannot separate what draft-ietf-httpapi-idempotency-key-header-07
requires from what this library decides. The distinction exists only as comment headings,
and those headings overclaim: scenarios filed under draft sections assert the 255-character
key limit, the comma rejection, and a 409 for a same-body/different-key request, none of
which the draft specifies. Response replay, which the next change builds on, is not
mentioned in the draft at all.

The mix is invisible to readers and unchecked by CI. Every new behaviour added to the suite
makes it worse, and the coming replay-header work adds several library decisions that would
otherwise be filed under a draft heading.

## What Changes

- Classify every scenario in the Gherkin suite as either draft-mandated or library policy,
  using one class tag per `Rule` block (`@draft` with a `@section:x.y` companion, or
  `@library`), with scenario-level overrides where a block mixes the two.
- Replace the plain-text section comments with `Rule` headings that name the draft section
  or state that the block is library policy.
- Classify all 49 existing scenarios in this pass. Partial classification is rejected.
- Add CI selection: run the draft set as its own step, and fail when any scenario resolves
  to no class or to both.
- Qualify the compliance claim in the README and on the docs landing page with the count of
  scenarios traced to a draft section, so the published claim matches the artifact.

The canonical feature file stays in `idempot-dev/website`; the local copy stays generated by
`scripts/sync-spec.sh`.

## Capabilities

### New Capabilities

- `spec-verification`: how the executable Gherkin suite is classified, how draft traceability
  is expressed, and what CI enforces about that classification.

### Modified Capabilities

None. No library behaviour changes in this change.

## Impact

- `tests/spec/idempotency.feature` (generated; authored upstream in `idempot-dev/website`)
- `.github/workflows/ci.yml`, `spec-compliance` job
- `package.json` scripts for the classified runs
- `README.md` and `docs/index.md` compliance claims
- No runtime code, no published package changes
